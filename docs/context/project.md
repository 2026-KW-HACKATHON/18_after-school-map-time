## 3. 서비스 기획

### 문제 (확정)

월계1동은 노후 건물, 계단, 턱, 고르지 않은 인도가 많고 어르신 비율이 높다.
그런데 "이 가게에 휠체어·유아차로 들어갈 수 있는지"에 대한 정보는 어디에도 정리되어 있지 않다.
기존 지도 서비스는 접근성 정보가 없거나 예/아니오 수준이라, 직접 가봐야 알 수 있다(헛걸음).

### 핵심 아이디어 (확정)

- 카카오맵 기반 웹 (2026-09-26 구글 지도에서 변경). "이 가게 들어갈 수 있나?"에 답한다.
- 가게별 **구조화된 접근성 필드**: 입구 턱 높이, 경사로 유무, 출입문 폭·형태, 내부 단차, 장애인 화장실, 엘리베이터
- **핵심 차별점:** 사용자가 이동 조건(휠체어 / 유모차 / 보행 보조기 / 목발 / 캐리어)을 고르면 **이용 가능한 곳만** 보여준다 — "각자에게 필요한 지도"
- **데이터:** 초기엔 팀원 직접 답사로 시딩 → 이후 주민 제보로 확장
- **제보 UX:** 입구 사진 한 장 또는 한 문장 + 위치 자동 입력 + 체크 몇 번.
  AI API가 사진에서 턱·경사로를 1차 판별하고, 다른 사용자의 확인으로 신뢰도가 올라간다.
- **지향점:** 불편을 겪은 당사자가 정보 제공자가 되는 선순환

### 기능 범위 — 초안 (팀 합의 전, MoSCoW)

**Must (MVP)**

| ID | 기능 |
|---|---|
| F1 | 카카오맵 위 월계1동 가게·시설 마커 |
| F2 | 구조화된 접근성 필드 (턱 높이 cm, 경사로, 문 폭 cm·형태, 내부 단차, 장애인 화장실, 엘리베이터) |
| F3 | 이동 조건 선택 → 판정 규칙에 따라 필터링. 마커는 가능 / 조건부 / 어려움 / 미확인 4단계 색 구분 |
| F4 | 장소 상세: 입구 사진, 필드값, 마지막 확인일 |
| F5 | 간단 제보: 사진 + 체크박스 + 현재 위치 자동 입력 |
| F6 | 팀 답사 시드 데이터 |

**Should:** AI 사진 1차 판별 / 한 문장 제보의 AI 구조화 / "아직 맞아요" 확인으로 신뢰도·확인일 갱신 / 제보 충돌 처리·검수 화면 / 어르신 친화 모드(큰 글씨)

**Could:** 가게 사이 보행 경로 접근성 / 사장님 직접 등록·"접근성 확인 가게" 배지 / 노원구 공공데이터 연동 / 제보 포인트·배지 / 스크린리더·음성 안내

**Won't:** 실시간 내비게이션, 네이티브 앱, 월계1동 외 지역 확장

### 인프라에 영향을 주는 기능 요구사항

| 요구 | 인프라 영향 |
|---|---|
| 제보 시 "현재 위치 자동 입력" | 브라우저 Geolocation API는 **HTTPS에서만 동작** → SSL 필수 |
| 입구 사진 업로드 | 폰 사진은 수 MB → Nginx `client_max_body_size` 상향, media 저장소·백업 필요 |
| AI 사진 판별 | 외부 API 응답이 느릴 수 있음 → Gunicorn·Nginx 타임아웃 여유 |
| 카카오맵 | JS 키는 카카오 개발자센터 플랫폼(Web)에 허용 도메인(개발 `localhost:8000`, 배포 도메인)만 등록. REST 키는 서버 전용 |
| 전시·주민투표 | 모바일 우선, 재시작 정책, DB 백업, 헬스체크 |

# 답사 가이드 — 시드 데이터 만들기 (F6)

> 팀원이 월계1동 가게를 직접 다니며 접근성 값을 재고, CSV 한 파일로 모아 한 번에 넣는 방법입니다.
> 한두 곳만 넣거나 고칠 때는 운영자 화면 **장소 등록**(`/ops/places/new/`)이 더 편합니다. 결과는 똑같이 '팀 답사' 기록으로 저장됩니다.

---

## 1. 준비물

| 준비물 | 용도 |
|---|---|
| 줄자 (1m 이상, cm 눈금) | 입구 단차, 출입문 폭 |
| 휴대폰 | 입구 사진, 위치 확인 |
| 답사 양식 [`places/data/survey/template.csv`](../places/data/survey/template.csv) | 엑셀·구글 시트로 열어서 한 가게 = 한 줄 |
| 사장님 인증 코드 (선택) | 운영자 화면 장소 수정에서 발급. 사장님께 드리면 가게 정보를 직접 관리할 수 있음 (`/owner/claim/`) |

## 2. 재는 방법

모르거나 못 쟀으면 **비워 두세요** ('모름'도 됩니다). 빈 칸은 저장하지 않아서, 나중에 다른 사람이 채울 수 있습니다.

| 칸 | 재는 법 | 적는 법 |
|---|---|---|
| 입구 단차(cm) | 문 앞 바닥에서 문턱·계단 꼭대기까지 **전체** 높이 | 숫자. 턱이 없으면 `0` |
| 계단 수(칸) | 계단 칸 수. 문턱 하나만 있으면 0 | 숫자 |
| 고정 경사로 | 입구에 설치된(치울 수 없는) 경사로 | `있음` / `없음` |
| 출입문 폭(cm) | 문을 끝까지 열었을 때 **실제로 지나갈 수 있는** 폭 | 숫자 |
| 출입문 형태 | | `자동문` `미닫이` `여닫이` `회전문` `문 없음` 중 하나 |
| 가게 안 단차 | 입구를 지난 뒤 가게 안에 턱·계단 | `있음` / `없음` |
| 장애인 화장실 | 가게 안에 휠체어로 쓸 수 있는 화장실 | `있음` / `없음` |
| 입장 도움 · 이동식 경사로 · 이동식 경사로 길이(cm) | 사장님께 여쭤보고, 경사로는 실물을 확인했을 때만 | `있음` / `없음`, 길이는 숫자 |

- **2층 이상·지하 가게**: `층`을 적고, `건물 이름`·`건물 주소`와 **건물 공용 입구** 값(`건물 입구 단차(cm)`, `건물 계단 수(칸)`, `건물 고정 경사로`, `건물 출입문 폭(cm)` …)과 `엘리베이터`도 적습니다.
  판정은 "건물 입구 → 층 이동(엘리베이터) → 가게 입구"를 모두 지나는 경로로 계산합니다. **엘리베이터를 비우면 휠체어·유아차 판정이 "아직 정보가 없어요"가 됩니다.** 같은 건물의 다른 가게 줄에도 같은 `건물 주소`를 적으면 한 건물로 묶입니다.
- **판정에 꼭 필요한 값**: 입구 단차·계단 수·고정 경사로·출입문 폭. 하나라도 비면 그 가게는 "아직 정보가 없어요"로 보일 수 있습니다.

## 3. 사진 찍는 법

- 입구 **정면**, 문턱·계단이 보이게 한 장. 파일 이름을 `입구 사진` 칸에 적습니다 (예: `wolgye-pharmacy.jpg`).
- **사람 얼굴·차량 번호판이 나오지 않게** 찍습니다 (기획 v2 4.4). 나왔다면 다시 찍어 주세요.
- 사진은 한 폴더(`survey_photos/`)에 모읍니다. 이 폴더는 레포에 올리지 않습니다 (`.gitignore`).
- 가져올 때 자동으로 가로·세로 1600px 이하로 줄이고, **촬영 위치(GPS) 같은 EXIF 정보를 지웁니다**.

## 4. 양식 채우기

| 칸 | 필수 | 설명 |
|---|---|---|
| 이름 | ✅ | 간판 이름. **이름 + 주소**가 같으면 같은 장소로 봅니다 (다시 넣어도 중복 안 됨) |
| 유형 | | `음식점` `카페` `편의점·마트` `약국` `병원·의원` `공공기관` `기타` |
| 주소 | | 도로명 주소 권장 |
| 위도 · 경도 | | 카카오맵에서 장소를 눌러 확인. **비워 두면 자동으로 찾습니다**: 주소로 먼저, 주소가 없거나 못 찾으면 가게 이름으로 월계1동 중심 3km 안에서 (새 장소만, 서버에 `KAKAO_REST_API_KEY` 필요). `--dry-run` 결과의 "위치 — 주소로 찾음/이름으로 찾음" 줄을 보고 맞는지 확인하세요 |
| 층 | | 1층이면 비워도 됨. 지하 1층은 `-1` |
| 확인일 | ✅ | 답사한 날짜 `2026-10-03` |
| 답사자 · 메모 | | 기록에 남습니다 ("답사: 강성훈 · 입구 오른쪽에 호출벨") |

- 둘째 줄의 `# 예시)` 줄처럼 **이름이 `#`으로 시작하는 줄은 읽지 않습니다.** 지우지 않아도 됩니다.
- 저장은 **CSV**로. 엑셀의 "CSV (쉼표로 분리)"와 "CSV UTF-8" 모두 읽을 수 있습니다.
- 다 채운 파일은 `places/data/survey/wolgye1.csv`로 저장해서 커밋합니다 → 누구나 같은 데이터를 다시 넣을 수 있음 (재현 가능성).

## 5. 넣기

### 5-1. 먼저 검사만 (`--dry-run`)

저장하지 않고 끝까지 해 본 뒤, 줄마다 **판정 결과를 미리** 보여줍니다. 잘못 적은 칸이 있으면 모든 줄의 문제를 한 번에 알려 주고 **아무것도 저장하지 않습니다.**

```bash
docker compose exec web python manage.py import_survey places/data/survey/wolgye1.csv --photos survey_photos --dry-run
```

```text
  3줄  [새 장소] 월계 약국
        휠체어: 혼자 들어가기 어려워요 — 입구 단차 15cm · 계단 수 1칸
        유아차: 혼자 들어가기 어려워요 — 입구 단차 15cm · 계단 수 1칸
        ...
[검사만 함 — 저장 안 됨] 새 장소 12곳 · 갱신 0곳 · 변경 없음 0곳 · 답사 기록 20건
```

### 5-2. 로컬에 넣기

```bash
docker compose exec web python manage.py import_survey places/data/survey/wolgye1.csv --photos survey_photos
```

### 5-3. 배포 서버에 넣기

CSV를 커밋해서 `develop`에 머지하고 `main`에 반영(릴리스)하면 배포 이미지에 들어갑니다. 사진은 레포에 없으므로 서버로 따로 복사합니다.

```bash
# 내 PC → 서버 (Git Bash)
scp -i <키 파일 경로> -r survey_photos ubuntu@<서버 IP>:~/survey_photos
```

```bash
# 서버에서
cd ~/teokeopne
docker compose -f docker-compose.prod.yml cp ~/survey_photos web:/tmp/survey_photos
docker compose -f docker-compose.prod.yml exec web python manage.py import_survey places/data/survey/wolgye1.csv --photos /tmp/survey_photos --user <운영자 아이디> --dry-run
# 결과를 확인한 뒤 --dry-run 을 빼고 다시 실행
```

- `--user`: 기록에 남길 작성자(운영자 계정 아이디). 생략하면 작성자 없이 저장됩니다.
- 넣은 뒤 지도(`/`)와 운영자 장소 목록(`/ops/places/`)에서 확인합니다.

## 6. 다시 답사했을 때

- 같은 파일을 다시 넣으면 **변경 없음**으로 건너뜁니다.
- 값을 고치고 `확인일`을 새 날짜로 바꿔 넣으면, 기존 기록은 이력으로 남고 새 값으로 판정이 바뀝니다.
- 비워 둔 칸은 기존 값을 지우지 않습니다.

## 7. 양식 칸을 바꾸려면

칸 이름은 접근성 필드 정의(`places/data/field_definitions.json`)에서 만듭니다. 필드를 추가·수정했다면 양식을 다시 만듭니다.

```bash
docker compose exec web python manage.py import_survey --template places/data/survey/template.csv
```

(테스트가 레포의 양식과 필드 정의가 일치하는지 확인합니다.)
